## Claim
Composio ran DeepSeek V4 Flash — a model that tops public leaderboards and is widely praised by developers as a "monster" — through 8 different agent harnesses (Claude Code, Codex, OpenCode, Pi, DeepAgents, and others) on 30 deliberately hard, multi-step SaaS tasks (Gmail, GitHub, Slack, Google Sheets). Across 240 runs the pass rate was 53.8% (129/240); only 6 of 30 workflows passed on every harness tested, and the identical model swung by as much as ~20 percentage points in pass rate purely from harness choice.

## Why it matters
Leaderboard rank is not a reliable proxy for production agent reliability — the harness/orchestration layer wrapping a model can matter as much as the model itself. This bears directly on how Hermes should evaluate any candidate model or harness change before adoption: cost-per-successful-task, not cost-per-token or benchmark score, is the right comparison frame.

## Underlying source
https://composio.dev/content/best-agent-harness-deepseek-v4-flash (Composio's own published eval, disclosed methodology: 8 harnesses, 30 tasks, 240 runs, live SaaS tools). Secondary coverage: https://venturebeat.com/orchestration/deepseeks-top-ranked-v4-flash-stumbles-on-real-agent-tasks-as-its-prices-surge

## Verification
Primary source is Composio's own benchmark page with disclosed methodology. Independently referenced by multiple unrelated outlets (VentureBeat, CryptoBriefing, Hitechub, HTX Insights) describing the same underlying dataset consistently. No indication of vendor bias against DeepSeek; Composio is a neutral agent-tooling vendor with a commercial interest in harness quality broadly, not in any one model's reputation.

## Potential workflow impact
Adopt "pass rate + cost-per-successful-task across multiple harnesses" as a standard evaluation axis before routing any Hermes agent-fleet task to a new model or harness, rather than trusting a single leaderboard score.

## Smallest shadow test
Retroactively apply Composio's cost-per-successful-task framing to 5-10 recent Hermes agent-fleet tasks (e.g., screener daily-pipeline steps) run under the current model/harness, and compare against one cheaper alternative harness on a sandboxed subset. Cheapest version: a single manual side-by-side run on one bounded task.

## Final disposition
Route to shadow-research backlog as an evaluation-methodology adoption candidate (not a model-swap decision — DeepSeek V4 Flash itself is not being proposed for production use). Observability only during the X Intelligence freeze.

## Claim
OpenAI quietly shipped an update to Codex's Multi-Agent v2 system letting a parent model (Sol or Terra) delegate bounded subtasks to a different, cheaper/faster model (Luna) instead of only spawning copies of itself — turning model choice into a per-task routing decision within one orchestrated coding session.

## Why it matters
This is a concrete, reproducible pattern for cutting agent-fleet compute cost: reserve the expensive frontier model for planning/review, route narrow execution work to a cheap model. Directly analogous to the cost-routing gap already flagged in prior digests (Nvidia Nemotron/NeMo Switchyard, ledger row 104) and squarely relevant to Hermes/OpenClaw agent-fleet economics.
