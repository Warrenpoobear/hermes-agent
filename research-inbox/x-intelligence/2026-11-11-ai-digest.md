## Claim
Claude Code release notes for 2.1.317-2.1.322 (Nov 3-10, 2026) include: 2.1.319 (Nov 6) "Fixed a sandbox escape when creating a worktree"; auto mode behind an LLM gateway or with telemetry/feature flags off no longer falls back to the built-in classifier (calls the server cannot check are asked about or denied; `CLAUDE_CODE_AUTO_MODE_SERVER=0` restores the old behavior); project settings files or plugins can no longer re-enable the server-side auto-mode check once it has been switched off outside the project. 2.1.318 (Nov 4): subagents stop instead of switching models when the model-switch setting is "Ask each time". 2.1.321 (Nov 9): mods Claude writes turn on without asking in auto/bypass modes, even with managed `allowUnsandboxedCommands: false`.

## Why it matters
Concrete, dated, vendor-documented changes to the permission and sandbox surface of a coding agent used on this stack (CI remediation, repo maintenance, scheduled routines). A sandbox escape fix and behavior changes to auto-mode fallback mean any governance assumption about "unsandboxed commands blocked" or "classifier fallback" should be re-checked against the installed version. The 2.1.321 note on mods bypassing managed unsandboxed-command restrictions is a policy-vs-behavior gap worth understanding.
